# SunPy 学習支援

SunPy とその関連パッケージのエラーを貼り付けると、AI が**答えではなく問いを返す**ブラウザ用チャットです。原因を教わるのではなく、自分で読み解けるようになることを目的にしています。

## 使い方

### 1. AI に接続する（最初の1回だけ）

画面右上の **設定** を開き、Anthropic の API キー（`sk-ant-` で始まる文字列）を貼り付けて **保存** を押します。キーは [console.anthropic.com](https://console.anthropic.com/) で取得できます。

キーはあなたのブラウザの中にだけ保存され、送信先は Anthropic の API のみです。共有パソコンを使っている場合は、終わったら設定を空欄にして保存すると削除できます。

### 2. セッションを始める

最初の画面で 3 つ選びます。

- **出題形式** — 「選択問題」は 4 択で切り分けます。デバッグの型を掴みたいときに向いています。「記述問題」は自分の言葉で説明するので、理解の穴がはっきり出ます。
- **対象パッケージ** — 選ばなくても構いません。貼り付けたエラーから `aiapy` や `drms` などを自動で判定します。
- **想定水準** — 入門・実務・上級。設問の深さが変わります。

### 3. エラーを貼り付ける

下の入力欄に**トレースバックの全文**を貼り付けて送信します。該当するコードや「たぶんここが怪しい」という自分の仮説も一緒に書くと、設問がより的確になります。

メールアドレスやホームディレクトリ名が含まれていた場合は、送信前にマスキング結果が表示されます。内容を確認してから **この内容で送信** を押してください。

### 4. 問いに答えていく

AI はまず **Gate A** で着眼点だけを渡します。ここで自力で気づけたら最短です。まだ足りなければ **もう一段ヒント**、それでも見えなければ **設問に進む** を押して **Gate B** に入ります。

Gate B は Lv1 観察 → Lv2 切り分け → Lv3 仮説 → Lv4 検証 → Lv5 修正 の順に進みます。今どこにいるかは画面上部のバーで確認できます。回答すると、AI は正誤を断定せずに次の問いを返します。

### 5. 「原因が分かった」を押す

原因が見えたら **原因が分かった** を押し、たどり着いた原因を根拠と一緒に書いて送信します。返ってくる判定は 3 つです。

| 判定 | 何が起きるか |
| --- | --- |
| 正解です | 図（SVG）付きの説明と出典が表示されます |
| あと一歩です | 答えは伏せたまま、足りない点を指摘する次の設問が続きます |
| 違います | 同じく答えは伏せたまま、別の角度からの設問が続きます |

どうしても分からないときは **わからない（開示）** を押すと、原因・根拠・修正方針・再発防止策がまとめて開示されます。

到達段階に応じて評価が付きます。★★★ は Gate A の着眼点だけで解けた場合、★★☆ は設問の誘導で到達した場合、★☆☆ は開示による解決です。

### 6. レポートを見る

解決したら **レポートを表示** で、到達した理解・掴んだこと・まだ曖昧な点・次に読むべきものがまとまります。セッションは自動保存され、左のサイドバーから後で続きを再開できます。

## 参照ライブラリ（精度を上げたいとき）

上部メニューの **参照ライブラリ** に、論文のアブストラクト・公式ドキュメントの該当節・変更履歴（CHANGELOG）を貼り付けて登録できます。登録した内容は以降の設問の切り口になり、「正解です」のときの出典もここから優先して選ばれます。

使っているバージョンの CHANGELOG を入れておくと、非推奨 API の削除やシグネチャ変更が絡むエラーで特に効きます。**最新情報を Web 検索で補う** をオンにすると、初手・判定・開示のときだけ Web 検索も併用します。

## よくある質問

**答えを先に教えてもらえませんか**

→ できません。それがこのツールの唯一の性格です。急いでいるときは **わからない（開示）** を押してください。1 手で開示まで飛べます。

**エラーの一部だけ貼っても動きますか**

→ 動きますが、精度は落ちます。トレースバックは最終行だけでなく全文を貼ってください。どのフレームで落ちたかが、設問の質をいちばん左右します。

**データや貼り付けた内容はどこかに保存されますか**

→ セッション履歴と参照ライブラリはあなたのブラウザ内にのみ保存されます。サーバーには送られません。貼り付けた内容は AI への問い合わせのため Anthropic の API にのみ送信されます。

**AI の言うことは信用できますか**

→ 誤ることがあります。示された修正方針は、必ず公式ドキュメントと実際の実行結果で確認してください。

**履歴を消したい**

→ ブラウザのサイトデータを削除すると、セッション履歴・参照ライブラリ・API キーがすべて消えます。

## 開発者向け

ビルド不要・依存ゼロの静的サイトです。

```bash
git clone https://github.com/<your-account>/sunpy-learning-assistant.git
cd sunpy-learning-assistant
python -m http.server 8000     # http://localhost:8000
```

**公開する** — リポジトリの Settings → Pages → Source を **GitHub Actions** にすると、`main` への push で `.github/workflows/pages.yml` が公開まで行います。API キーは各利用者のブラウザに保存されるため、リポジトリに含める必要はありません。

**単一ファイル版を作る** — `node tools/build-standalone.mjs` で CSS と JS を埋め込んだ `dist/index.html` を生成します。配布用に 1 ファイルで渡したいときに使ってください。生成物なので手で編集せず、必ずビルドし直してください。

### 構成

```
sunpy-learning-assistant/
├── index.html                 画面の骨組み
├── assets/
│   ├── css/style.css          配色（sunpy.org のダークテーマ準拠）
│   └── js/
│       ├── config.js          パッケージ定義・落とし穴・到達段階
│       ├── storage.js         保存層（window.storage / localStorage / メモリ）
│       ├── analyzer.js        トレースバック解析・パッケージ判定・マスキング
│       ├── prompts.js         AI へのプロンプト（ソクラテス式の規則）
│       ├── api.js             Anthropic API クライアント
│       └── app.js             対話の進行
├── tools/build-standalone.mjs 単一ファイル版のビルド
├── dist/index.html            ビルド生成物
├── docs/PROMPTS.md            プロンプト設計の説明
└── .github/workflows/pages.yml
```

### 設計の要点

AI に守らせている規則は `assets/js/prompts.js` にあります。

1. 原因・修正コードを先に出さない
2. 1 ターンにつき問いは 1 つ
3. Lv1 観察 → Lv2 切り分け → Lv3 仮説 → Lv4 検証 → Lv5 修正 の順に誘導
4. 存在しない関数・引数・DOI・バージョンを捏造しない
5. 出力は JSON のみ（UI が構造化して描画するため）

Gate を分けているのは、最初から選択肢を見せると消去法で当たってしまい学習にならないからです。着眼点だけを渡す Gate A を挟み、そこで解けた人に ★★★ を出します。

設問の質を上げたいときは、`assets/js/config.js` の `packages[].pitfalls` に実際に踏んだ落とし穴を書き足すのがいちばん効きます。詳しくは [CONTRIBUTING.md](CONTRIBUTING.md) と [docs/PROMPTS.md](docs/PROMPTS.md) を参照してください。
